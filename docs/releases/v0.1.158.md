# rLogs v0.1.158

## Highlights

- Recovers an otherwise-unresolved active scene after a mid-session packet-capture attach from recurring team state when the update belongs to the already-known local character.
- Accepts only positive, catalog-known local scene IDs and ignores remote party members and unknown scene values.
- Treats team scene state as a recovery-only fallback: it cannot overwrite richer canonical scene, line, or instance evidence, and repeated roster echoes cannot drive unnecessary overlay refreshes.
- Retains the run-scoped local skill-observation receipt, per-participant timeline completeness disclosure, and public report projection revision 14 from 0.1.157.

## Compatibility

- Platform: Windows x64
- Game deployment: Global
- Game build(s): observed 25247556, using the reviewed 24687926 compatibility epoch for stable packet and display identities
- Canonical event schema: 10
- Public report schema: 17; projection revision 14; public reconciliation schema 22; combat timeline schema 9

## Capability status

- Available: packet-only scene recovery from authoritative scene packets and recurring known-local team state, exact local outbound skill rows, receipt-proven complete local skill coverage, truthful per-participant timeline disclosure, multi-adapter capture continuity, opt-in ExitLag loopback capture, local Automarker preset Save/Save As/Load, and the unified overlay canvas.
- Conservative: `Complete` proves uninterrupted observational coverage produced by an honest official rLogs client. It is not cryptographic attestation against a modified client.
- Locked: native party-visible Automarker placement remains disabled until its game-owned dispatch path and server-observed lifecycle are fully verified for the current build.
- Paused: historical public-report projection backfill remains disabled pending an explicit operator rollout and deployed forward/rollback canary.

## Known limitations

- Other players' complete skill timelines require their own compatible synchronized POV logs.
- A scene can remain unresolved when rLogs starts mid-session until either a scene-bearing transition packet or a recurring update for the already-known local team member appears.
- Projection revision 14 must be deployed to the verifier/backend before a 0.1.158 desktop release is published.
