# rLogs v0.1.157

## Highlights

- Seals a run-scoped local skill-observation receipt so an official rLogs capture can distinguish complete local skill coverage from merely exact individual cast rows.
- Marks only the receipt-proven local participant as `Complete`; every other participant remains `Partial` or `Unavailable` until a compatible POV is synchronized.
- Binds completeness to the authorized outbound `World.UseSlot` route, exact actor and entity, deployment, client build, protocol-pack digest, authoritative run bounds, retained cast sequences, decoder failures, data gaps, and capture-queue saturation.
- Remaps receipt evidence through both per-run segmentation and privacy filtering, and fails closed when a referenced event was not retained.
- Publishes public report projection revision 14 and keeps the correct website, Cloudflare verifier, and backend contracts compatible with revisions 13 and 14.
- Retains the packet-backed scene refresh and stale-scene clearing fixes from 0.1.156.

## Compatibility

- Platform: Windows x64
- Game deployment: Global
- Current observed game build: 25247556, using the reviewed 24687926 compatibility epoch for stable packet and display identities
- Canonical event schema: 10
- Public report schema: 17; projection revision 14; public reconciliation schema 22; combat timeline schema 9

## Capability status

- Available: exact local outbound skill rows, receipt-proven complete local skill coverage, truthful per-participant timeline disclosure, packet-authoritative scene presentation, multi-adapter capture continuity, opt-in ExitLag loopback capture, local Automarker preset Save/Save As/Load, and the unified overlay canvas.
- Conservative: `Complete` proves uninterrupted observational coverage produced by an honest official rLogs client. It is not cryptographic attestation against a modified client.
- Locked: native party-visible Automarker placement remains disabled until its game-owned dispatch path and server-observed lifecycle are fully verified for the current build.
- Paused: historical public-report projection backfill remains disabled pending an explicit operator rollout and deployed forward/rollback canary.

## Known limitations

- Other players' complete skill timelines require their own compatible synchronized POV logs.
- A scene can remain unresolved when rLogs starts mid-session and no scene-bearing packet has appeared. Steady-state entity traffic cannot safely reconstruct scene identity.
- Projection revision 14 must be deployed to the verifier/backend before a 0.1.157 desktop release is published.
