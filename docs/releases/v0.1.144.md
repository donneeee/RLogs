# rLogs v0.1.144

## Highlights

- Adds exact status-effect lifecycle spans to the desktop Combat History timeline. Spans use each player's graph color and visibility control and appear only for an unambiguous packet-observed Applied-to-Removed/Consumed lifecycle.
- Uses the full trusted, build-aware status catalog for desktop lifecycle names and explicitly labels unresolved identities as unlocalized instead of inventing a buff, debuff, or display name.
- Publishes and renders synchronized public timeline schema 8 status lifecycles on the website, including canonical multi-POV clock alignment and the same player visibility coupling.
- Hardens synchronized rDPS range publication: incomplete clocks, swapped player tracks, duplicate or out-of-range buckets, forged participant totals, and per-bucket provider/recipient conservation failures now fail closed.
- Keeps the shared Overlay canvas transparent during play while retaining the darkened editing canvas and translucent module boundaries.

## Compatibility

- Platform: Windows x64
- Game deployment: Global
- Game build(s): reviewed pack 24687926; ordinary parsing, localization, maps, and non-seasonal compatibility carry forward, while build-sensitive mechanics and rDPS identities remain evidence-gated
- Public report schema: 17; projection revision 12; public reconciliation schema 21; combat timeline schema 8
- Combat History schema: 1, backward-compatible through default-empty status evidence fields
- Overlay layout schema: 2, backward-compatible; passive mode uses only each module's configured background opacity

## Capability status

- Available: Exact desktop and website skill/death/status timeline lanes, trusted status presentation, synchronized-POV lifecycle alignment, fail-closed rDPS range clocks and ledgers, transparent passive shared-canvas widgets, editor-only dark canvas and module bounds, Done/Escape edit exit, and configurable Scroll Lock visibility.
- Locked: Native in-game automarker placement remains disabled until a current-build outbound placement route and matching visible lifecycle are proven safely. Historical projection publication remains paused until a staging forward-publication and queued inverse-rollback exercise is recorded.

## Known limitations

- Existing saved local histories without retained status transitions cannot display lifecycle spans unless their original evidence can be replayed. Existing public reports remain on their immutable timeline version until guarded reprojection is enabled.
- Automatic late-route discovery for modern ExitLag redirection remains follow-up work; manual Npcap Loopback selection remains available.
- Status spans intentionally omit incomplete, duplicate-terminal, ambiguous, non-participant, and cross-runtime evidence. Unknown effects remain visibly unlocalized.
