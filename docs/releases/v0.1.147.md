# rLogs v0.1.147

## Highlights

- Keeps the shared overlay canvas painted across live feed revisions. Existing map, player, party, target, objective, action, and mechanic nodes are reconciled in place instead of replacing the visible surface and causing a flash.
- Places Lock, Hide, and Done in the canvas-level control bar, independent of the mechanics map. Hide closes the shared overlay surface without changing the saved layout; Scroll Lock or the main app restores it.
- Keeps Escape equivalent to Done while editing: it returns the canvas to transparent click-through play mode without hiding any configured overlay modules.
- Uses stable mechanic-instance identity during live updates, including duplicate effects on different targets, while still replacing genuinely different action entries.
- Couples each Combat History participant control to that player's graph trace, event lane, skill markers, status events, and death markers, with matching accessible pressed state.
- Removes redundant raw scene-number chrome from Combat History while retaining the exact scene ID as localized evidence metadata.

## Compatibility

- Platform: Windows x64
- Game deployment: Global
- Game build(s): reviewed pack 24687926; ordinary parsing, stable localization, and real-map presentation carry forward only through a digest-verified compatibility epoch, while build-sensitive mechanics and rDPS identities remain evidence-gated
- Public report schema: 17; projection revision 12; public reconciliation schema 21; combat timeline schema 8
- Combat History schema: 1, backward-compatible; event lanes are participant-controlled independently of the selected graph metric
- Overlay layout schema: 2, backward-compatible

## Capability status

- Available: Stable in-place shared-canvas updates, independent canvas-level Hide/Lock/Done controls, Escape-to-play mode, Scroll Lock visibility recovery, transparent click-through play mode, participant-controlled graph and event timelines, digest-verified real-map carry-forward, and canonical-clock desktop rDPS history graphs.
- Locked: Native in-game automarker placement remains disabled until a current-build outbound placement route and matching visible lifecycle are proven safely. Multi-POV death merging remains disabled until each secondary death is derived from a verified sealed artifact with its own server-time evidence and collision-safe identity mapping. Historical projection publication remains paused until a deployed isolated staging canary passes.

## Known limitations

- Secondary-POV death rows are not copied from public/client timeline JSON. The public death schema does not yet retain each death event's own server time, so safely aligned multi-POV death merging requires a later sealed-replay schema slice.
- The local forward/rollback rehearsal validates the transaction layer but does not replace the final hosted-verifier staging canary, so production historical reprojection remains paused.
- Existing public reports remain on their immutable timeline version until guarded reprojection is enabled. Reports without retained exact skill, status, hostile-cast, or death evidence cannot synthesize those events later.
- Automatic late-route discovery for modern ExitLag redirection remains follow-up work; manual Npcap Loopback selection remains available.
- Native in-game automarker transmission remains unavailable; saved scene-family marker presets and preview behavior do not send placement packets.
