rLogs v0.1.84 makes live BPSR traffic discovery packet-first across supported and unknown client executables.

- Selects the game connection from the exact early BPSR scene/login server signature used by established Star Resonance parsers instead of admitting every socket owned by a scanned process.
- Keeps unidentified TCP frames in a two-second, memory-bounded transient queue and discards them before persistence, reconstruction, or protocol decoding.
- Expires a confirmed four-tuple after ten idle seconds so a later reused connection must prove the BPSR signature again.
- Starts passive packet-signature monitoring even when no recognized game executable is present, allowing future or differently named client builds to reach the local overlay and history pipeline.
- Keeps packet-only client identity explicitly unverified, with automatic submissions and exact-build calculations disabled until independent build evidence is available.
- Uses recognized Global, Steam, Epic, SEA, Asia, and TW processes only as optional stronger build/channel receipts and upgrades an active packet bootstrap when one appears.
- Falls back to the recognized executable name when Windows blocks a non-Steam executable-path query, fixing standalone-client startup without assigning a geographic region from the launcher name.
- Updates the bundled Blue Protocol: Star Resonance game plug-in to v0.1.14.
