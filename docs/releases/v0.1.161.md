# rLogs v0.1.161

## Highlights

- Replaces the withdrawn private 0.1.160 Automarker readiness build.
- Safely provisions the hash- and signature-pinned WinDivert 2.2.2 driver from an elevated rLogs process through a false-filter read-only handle.
- Starts a passive `SNIFF | RECV_ONLY` SYN observer for the exact local game process and connection epoch without retaining raw packets.
- Displays localized, sanitized Automarker stages for new-connection wait, native readiness, marker-carrier wait, server Return confirmation, and bounded readiness failures.
- Privately arms the one-marker coordinator only after exact preset, session, build, pack, scene, actor, tuple, epoch, freshness, and baseline validation.

## Compatibility

- Platform: Windows x64
- Game deployment: Global
- Game build(s): observed 25247556, using the reviewed 24687926 compatibility epoch for stable packet and display identities
- Canonical event schema: 10
- Public report schema: 17; projection revision 14; public reconciliation schema 22; combat timeline schema 9

## Capability status

- Available: read-only Automarker process/socket readiness observation with visible sanitized stages, local preset Save/Save As/Load, packet-only local identity and scene recovery, combat history timelines, and the unified overlay canvas.
- Conservative: readiness and coordinator state are exact-session, build, pack, scene, tuple, actor, connection-epoch, and freshness scoped and invalidate on any discontinuity.
- Locked: native party-visible Automarker placement remains disabled until the active held-carrier, checksum/send, server-confirmation, and final teardown path is fully verified.

## Known limitations

- rLogs must be launched as administrator before the game creates the observed BPSR connection so the passive worker can provision WinDivert and prove the initial outbound SYN.
- This private test build observes and displays readiness evidence but does not place markers automatically.
- Multi-marker activation remains fail-closed while the one-marker native dispatch path is completed first.
