# rLogs v0.1.154

## Highlights

- Repairs stale live scene identity after dungeon, world, or line-route handoffs by reconciling a uniquely known scene from later authoritative dungeon snapshots instead of depending only on the first entry packet.
- Keeps the prior and newly discovered capture adapters active together for the full monitoring session, so a VPN, ExitLag, loopback, or server-route change does not strand rLogs on the old scene stream.
- Adds an explicit ExitLag compatibility option. It remains off by default and takes effect when monitoring is restarted.
- Allows a localized read-only native scene observation to update the combat presentation without granting Automarkers or Mechanics Map authority. Unreviewed map geometry and encounter mechanics are cleared on an identity change.
- Preserves the overlay regression fixes: shared preview/live transparency, stable Dummy button sizing, transparent passive canvas surfaces, flash-resistant rendering, tier-zero item presentation, and independent overlay/map launch controls.

## Compatibility

- Platform: Windows x64
- Game deployment: Global
- Current observed game build: 25247556, using the reviewed 24687926 compatibility epoch for stable packet and display identities
- Public report schema: 17; projection revision 12; public reconciliation schema 21; combat timeline schema 8
- Historical semantics remain immutable: mechanics, native marker placement, uploads, and rDPS formula authority are not expanded by this release.

## Capability status

- Available: packet-authoritative scene repair, multi-adapter capture continuity, opt-in ExitLag loopback capture, cross-build stable scene presentation, local Automarker preset Save/Save As/Load, and the unified overlay canvas.
- Locked: native party-visible Automarker placement remains disabled until its game-owned dispatch path and server-observed lifecycle are fully verified for the current build.
- Paused: historical public-report projection backfill remains disabled until generalized source-version handling and an isolated deployed forward/rollback canary are complete.

## Known limitations

- The read-only native observer is a dungeon presentation fallback; it does not currently expose a line/channel identifier and is not the authority for canonical logs.
- Exact live validation is still required on the gaming PC for a world or line change under its actual network route. The mirrored capture host verified current BPSR traffic and discovery signatures with zero capture loss.
- ExitLag compatibility should be enabled only when ExitLag is in use. Restart monitoring after changing the option.
- Mechanics Map content remains exact-scene and exact-authority gated. A newly recognized scene can clear stale map content without inventing a map or mechanic pack.
