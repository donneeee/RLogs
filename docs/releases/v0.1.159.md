# rLogs v0.1.159

## Highlights

- Fixes packet-only cold attaches on a mirrored adapter by deriving the local character identity from the server's self-only `SyncToMeDelta` route.
- Uses that independently established identity to accept scene recovery only from the matching local team member; roster order, leader state, position, HP, and remote members are never used to guess the player.
- Keeps recurring team scene state recovery-only, so it cannot overwrite richer canonical scene, line, or instance evidence.
- Reconciles the combat overlay, mechanics map, and Automarkers to the same latest exact scene, including unique dungeon/objective recovery when a transition packet was missed, while ambiguous evidence remains unresolved.
- Removes the session-sticky scene latch that could leave live surfaces on a previous dungeon and clears scene-bound mechanics state whenever the exact scene changes.
- Enlarges the uncircled, player-colored skull-and-crossbones death markers and adds a dark contrast edge without changing their layout or interaction target.
- Retains the run-scoped local skill-observation receipt, per-participant timeline completeness disclosure, and public report projection revision 14 from 0.1.157.

## Compatibility

- Platform: Windows x64
- Game deployment: Global
- Game build(s): observed 25247556, using the reviewed 24687926 compatibility epoch for stable packet and display identities
- Canonical event schema: 10
- Public report schema: 17; projection revision 14; public reconciliation schema 22; combat timeline schema 9

## Capability status

- Available: packet-only local identity and scene recovery from authoritative self/team routes, exact local outbound skill rows, receipt-proven complete local skill coverage, truthful per-participant timeline disclosure, multi-adapter capture continuity, opt-in ExitLag loopback capture, local Automarker preset Save/Save As/Load, and the unified overlay canvas.
- Conservative: `Complete` proves uninterrupted observational coverage produced by an honest official rLogs client. It is not cryptographic attestation against a modified client.
- Locked: native party-visible Automarker placement remains disabled until its game-owned dispatch path and server-observed lifecycle are fully verified for the current build.
- Paused: historical public-report projection backfill remains disabled pending an explicit operator rollout and deployed forward/rollback canary.

## Known limitations

- Other players' complete skill timelines require their own compatible synchronized POV logs.
- A cold mid-session attach outside a uniquely identifiable dungeon can remain unresolved until an authoritative scene-bearing update is observed. rLogs does not infer the local player from an ambiguous party roster or guess between scenes that share evidence.
- Projection revision 14 must be deployed to the verifier/backend before a 0.1.159 desktop release is published.
