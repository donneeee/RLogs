# rLogs v0.1.136

## Highlights

- Adds death skulls to the desktop History timeline using exact retained death events when available.
- Shows a hover- and keyboard-accessible cause-of-death summary with the terminal hit, exact death time, damage details, and the bounded two-second recent-hit context.
- Resolves participant, monster, and ability names only from the exact event-time identity and reviewed build catalog; stale, ambiguous, or mismatched presentation fails closed to authoritative identifiers.
- Keeps legacy histories usable with their existing one-second death markers while clearly withholding causes that those records cannot prove.

## Compatibility

- Platform: Windows x64
- Game deployment: Global
- Game build(s): 24687926
- Public report schema: 17; projection revision 9; public reconciliation schema 20; combat timeline schema 5

## Capability status

- Available: Packet-proven private death-event retention; desktop History death skulls and cause summaries; new-report public death markers and cause summaries; exact difficulty publication; website timeline playback, event navigation, time-sliced DPS inspection, player-colored death skulls, accessible death details, and a shared full-run overview navigator.
- Locked: Historical report backfill to timeline schema 5 remains disabled until the backfill producer and target are upgraded and verified together. Native in-game marker placement remains locked behind current-build packet proof and a safe end-to-end placement path.

## Known limitations

- Histories recorded without exact death events retain one-second death markers, but cannot provide a packet-proven cause summary.
- Death causes use authoritative numeric actor and ability identifiers when exact event-time or exact-build presentation is unavailable; names are never borrowed or invented.
- Direct-source naming and complete boss-skill localization remain limited by the event identities and reviewed exact-build catalogs present in the captured record.
