# rLogs v0.1.160

## Highlights

- Adds the private read-only Automarker readiness worker to the real desktop lifecycle.
- Verifies the exact local game process, SYN-owned socket epoch, pinned WinDivert runtime, driver signature/version, BFE state, REFLECT ordering preflight, and checksum helper without modifying or transmitting packets.
- Retains exact private Automarker carrier and successful Return evidence while keeping raw network identities out of HTTP, IPC, serialization, and logs.
- Clears stale scene-bound overlay, Mechanics Map, and Automarker context when native scene authority disappears instead of retaining the previous dungeon.
- Adds signature-first offline mirrored-capture discovery so scene-transition research excludes unrelated TCP traffic while preserving unknown BPSR routes.

## Compatibility

- Platform: Windows x64
- Game deployment: Global
- Game build(s): observed 25247556, using the reviewed 24687926 compatibility epoch for stable packet and display identities
- Canonical event schema: 10
- Public report schema: 17; projection revision 14; public reconciliation schema 22; combat timeline schema 9

## Capability status

- Available: read-only Automarker process/socket readiness observation, local Automarker preset Save/Save As/Load, packet-only local identity and scene recovery, combat history timelines, and the unified overlay canvas.
- Conservative: readiness evidence is exact-session, build, pack, scene, tuple, and connection-epoch scoped and invalidates on any discontinuity.
- Locked: native party-visible Automarker placement remains disabled until the active held-carrier, checksum/send, server-confirmation, and teardown path is fully verified.

## Known limitations

- The passive readiness worker must start before the game creates the observed TCP connection so it can prove the initial outbound SYN.
- This private test build does not place markers. It captures the readiness evidence required for the subsequent one-marker active canary.
- A cold mid-session attach can remain unresolved until the game establishes a new BPSR connection or the operator reconnects after starting rLogs.
