# rLogs v0.1.134

## Highlights

- Makes saved marker presets usable from the Mechanics Map picker with an immediate high-contrast local preview at their exact saved coordinates.
- Keeps marker setups isolated to their exact dungeon scene family, including shared M1-M20 families without leaking presets into related but different scenes.
- Adds a controlled current-build marker capture harness that binds six placements to the initiating actor, exact executable and protocol pack, action timestamps, and preserved network-flow evidence for safe protocol research.
- Gates desktop weapon, module, and module-effect names by exact deployment, build, and protocol identity so stale names fail closed to numeric unlocalized labels.
- Retains terminal combat and rDPS facts in the final reducer bucket, including fractional and exact whole-second run endpoints, with five-player conservation coverage.

## Compatibility

- Platform: Windows x64
- Game deployment: Global
- Game build(s): 24687926
- Public report schema: 15 (unchanged); public reconciliation schema 18 (unchanged)

## Capability status

- Available: Manual marker preset authoring, Save, Save As, exact-context persistence, scene-family filtering, and selection-driven host-session local preview on the Mechanics Map; exact-build desktop weapon/module/effect localization; terminal-bucket combat and rDPS retention.
- Locked: Reading the game's currently placed markers and transmitting a saved preset as in-game party markers. Both remain disabled until current-build packet semantics and an end-to-end safe placement path are proven from controlled captures.

## Known limitations

- Preview draws markers only in the local rLogs overlay; it does not place or change markers in the game for party members.
- Presets must currently be entered manually because capture-current is locked.
- A preview is bound to the current host session and exact build/scene/map/family context, expires after five minutes, and is cleared on scene transition or disposal.
- The controlled capture harness collects and correlates evidence but does not itself identify marker packet semantics, replay traffic, access process memory, or unlock native placement.
