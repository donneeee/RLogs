# rLogs v0.1.163

## Highlights

- Replaces the withdrawn private 0.1.162 Automarker readiness build.
- Starts the passive native observer before capture ingress and scene discovery, then classifies a process-owned connection candidate against the exact parser-confirmed BPSR socket.
- Promotes confirmed socket readiness independently of the later marker request, allowing the user to place Marker 1 at any later time while the same connection remains live.
- Replaces ambiguous readiness booleans with five explicit sanitized checkpoints: observer ready, SYN candidate observed, BPSR tuple confirmed, marker carrier observed, and server Return confirmed.
- Keeps the preset file schema at version 4 while advancing only the runtime view contract to version 5.

## Compatibility

- Platform: Windows x64
- Game deployment: Global
- Game build(s): observed 25247556, using the reviewed 24687926 compatibility epoch for stable packet and display identities
- Canonical event schema: 10
- Public report schema: 17; projection revision 14; public reconciliation schema 22; combat timeline schema 9

## Capability status

- Available: early read-only Automarker connection observation, exact parser/socket correlation, explicit localized readiness checkpoints, local preset Save/Save As/Load, packet-only identity and scene recovery, combat history timelines, and the unified overlay canvas.
- Conservative: private connection candidates expire while awaiting parser classification; a confirmed native flow then remains bound to its exact process, tuple, and connection epoch until an authoritative discontinuity.
- Locked: native party-visible Automarker placement remains disabled until the active held-carrier, checksum/send, server-confirmation, retransmission, and deterministic teardown path is fully verified.

## Known limitations

- rLogs must be launched as administrator before the game so it can provision the reviewed passive driver and observe new game connections.
- This private test build observes and displays readiness evidence but does not place markers automatically.
- Multi-marker activation remains fail-closed while the one-marker native dispatch path is completed first.
